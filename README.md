# SNT Pipelines Orchestrator

An OpenHEXA static webapp that lets a country team **see, configure and run the whole SNT
stratification process** from one screen, no code required. It presents all official SNT pipelines
(18, from [`snt_development`](https://github.com/BLSQ/snt_development)) as a guided,
one-step-at-a-time walkthrough in **French or English**: live status per pipeline, a parameter
form, Run, outputs and the HTML report in-app.

The deployed app is **identical in every workspace**. What a workspace contributes — which pipelines
are installed there, with their IDs and parameters — is a `pipeline_cards.json` in that workspace's
own file storage, generated by the companion [`create_pipeline_cards`](pipelines/create_pipeline_cards/)
pipeline. **Changing the configuration means running a pipeline, not redeploying the app.**

> **Agent-driven repo.** Built with Claude Code. Agent instructions are in [`CLAUDE.md`](CLAUDE.md);
> this README is the human overview.

## Common tasks

- **A newly installed pipeline doesn't show up, or a run says the configuration is out of date:**
  run `create_pipeline_cards` in that workspace (no parameters) and refresh the app.
- **Set up a new workspace:** create the webapp with its four scopes and deploy the five files,
  **then** install and run `create_pipeline_cards` — in that order. Checklist:
  [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md#new-workspace-checklist).
- **Change the app:** edit `webapps/orchestrator/` and deploy the changed file(s). For a full bundle
  or a large file, dragging the file(s) into the webapp in the OpenHEXA UI is often quickest.
- **Edit a pipeline description:** `webapps/orchestrator/pipeline_descriptions.json` — **write both
  languages** (`{ "en": "…", "fr": "…" }`).
- **Add a genuinely new step to the process:** add a node to `pipeline_map.json` and a description,
  deploy, then re-run the generator in each workspace.

## Working with the agent

Open the repo in Claude Code and describe what you want ("make the Run button do X", "set up the
orchestrator in workspace Z"). The agent needs the **OpenHEXA MCP server** to look things up and
deploy.

**Guardrails are enforced, not just documented.** The agent asks before any git/GitHub write, never
runs anything destructive or history-rewriting, and hands faster-by-hand steps back to you.
`.claude/hooks/block-destructive-git.js` hard-denies destructive commands (`git reset --hard`,
`push --force`, `rebase`, `clean`, branch deletion, `gh repo delete`, … — see the hook) whatever the
agent is asked. If you want one of those, run it yourself.

## Development workspaces

The app is developed in **`snt-app-dev`**, where all 18 pipelines are installed. **`snt-testing`**
has only a subset, which is useful for seeing the greyed-out state.
